## Phase 2 — Feature: Trade-specific scoring UX teasers for free tier

### `server/routes/leadsSearch.ts`

**Problem:** Free-tier users saw `"Verified signal"` badge on ALL lead cards regardless of trade. This gave zero insight into why a lead matched their trade — a missed conversion opportunity.

**Fix:** Replaced static `buildReasons()` with `buildPreviewReasons(lead: Lead)`:
- Extracts the first `Trade match:` keyword from the lead's real `scoreReasons` (generated by the scorer for the user's trade)
- Returns up to 2 keywords as `"Trade teaser: <keyword>"` format strings
- Falls back to first `Related:` keyword if no trade match
- Final fallback remains `"Paid preview - unlock buyer, deadline, exact value, and action route"`

**Result:** Free-tier electricians scanning B14 now see `"EV CHARGER"` or `"REWIRE"` grey badges on relevant leads instead of the generic fallback. Free-tier plumbers see `"BOILER"` or `"BATHROOM"`. The specific keyword is real (drawn from scorer output) but deliberately shown without the `"— YOUR TRADE"` highlight so free users understand they're seeing a teaser, not the full paid reason set.

### `src/pages/FindJobsPage.tsx` — parseTradeReasons()

Added handler for `"Trade teaser: ..."` format:
```typescript
const tradeTeaser = r.match(/^Trade teaser: (.+)/);
if (tradeTeaser) {
  out.push({ label: tradeTeaser[1].toUpperCase(), highlight: false });
  continue;
}
```
Uses `highlight: false` (grey badge) to distinguish teasers from paid reasons (which use yellow `highlight: true`).
